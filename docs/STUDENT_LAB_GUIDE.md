# 멀티클라우드 온라인 실습 안내

영상은 개념·도식·명령어 예시로 구성되며 실제 콘솔 녹화가 아닙니다. 계정·리전·네트워크·사양은 운영자가 배포한 안내를 우선합니다. 서비스가 제공되지 않으면 임의로 개인 결제 자원을 만들지 말고 운영자에게 문의합니다.

## 공통 준비 (AWS/NHN 각 시작 시)
1. 지정 계정/프로젝트·리전·현재 역할을 기록합니다. 키와 비밀번호는 적지 않습니다.
2. 제공된 서버가 있는지 먼저 확인합니다. 이미 있으면 중복 생성하지 않습니다.
3. 승인된 사양·접속 주소·키페어·종료 기준을 확인합니다.
4. 네트워크 다이어그램에 사용자→웹→DB 흐름과 공개 범위를 적습니다.

## 1. 네트워크와 접속
- AWS: 제공 VPC/Subnet과 해당 라우팅 테이블 연결, 공인 주소 필요 여부, Security Group 확인.
- NHN: 제공 VPC/Subnet과 경로, Floating IP 연결 대상, Security Groups 확인.
- SSH는 필요한 관리 출발지에서 TCP 22 접근을 허용합니다. 다른 포트나 모든 출발지를 불필요하게 열지 않습니다.
- MobaXterm: Session → SSH → Remote host에 제공 주소, Specify username에 이미지 사용자(지정 Ubuntu라면 일반적으로 ubuntu), Advanced SSH settings → Use private key에 제공 키를 지정합니다.
- 실패: timeout은 주소·경로·포트 허용, publickey 오류는 이미지 사용자·키 대응부터 점검합니다.
- 성공: hostname, whoami, /etc/os-release로 작업 서버와 OS를 확인합니다.

## 2. 동일 웹 앱 배포
ZIP의 demo-app 전체를 사용합니다. index.html 하나만 옮기지 않습니다.
실습 서버의 기존 사이트를 덮어쓰지 않도록 설정과 파일을 먼저 확인합니다.

```bash
sudo apt-get update
sudo apt-get install -y nginx
sudo systemctl enable --now nginx
sudo nginx -t
curl -I http://127.0.0.1/
```

파일을 서버의 임시 작업 폴더에 올린 후 실제 document root를 확인하여 배치합니다. 기본 예시 경로는 /var/www/html입니다. 기존 파일이 있다면 먼저 백업합니다.

```bash
sudo cp -r demo-app/. /var/www/html/
curl http://127.0.0.1/
```

외부 브라우저로 제공 서버 주소를 확인합니다. 디자인과 버튼도 동작해야 합니다. 이 앱의 환경 선택과 성공 문구는 정적 JavaScript 동작 확인용이며 AWS/NHN API나 DB 상태를 검사하지 않습니다.

## 3. 객체 저장소
- AWS S3의 지정 버킷/접두사, NHN Object Storage의 지정 컨테이너/접두사를 사용합니다.
- 개인정보 없는 작은 파일을 업로드하고 정확한 키·크기·유형을 기록합니다.
- 인증된 읽기와 익명 요청을 구분합니다. 비공개 자료가 익명 접근을 거부하면 정상일 수 있습니다.
- 공개 웹 실습은 별도 자원에서 진행합니다. LMS 영상 보관 버킷을 공개하지 않습니다.
- 서명 URL·토큰·키를 제출하지 않습니다.

## 4. 데이터베이스
- 운영자가 제공한 DB 상품·엔드포인트·포트·DB 이름·실습 사용자를 확인합니다.
- DB는 웹 서버에서 필요한 내부 접근을 우선합니다. 편의를 위해 모든 IP에 공개하지 않습니다.
- 준비 상태와 DB 보안 그룹, 연결 출발지와 인증정보를 구분합니다.
- 제공 Ubuntu 서버에 MySQL 클라이언트가 필요하고 설치가 허용되었다면 `sudo apt-get install -y mysql-client`로 설치합니다.

```bash
mysql -h DB_ENDPOINT -P 3306 -u LAB_USER -p
```

프롬프트에서 비밀번호 입력 후 `SELECT 1;`, `SELECT DATABASE();`를 실행합니다. 변수 이름은 실제 제공 값으로 바꿉니다. 임의의 데이터 변경·삭제 쿼리는 실행하지 않습니다.

## 5. 운영 점검과 제출
- 웹 내부/외부 응답, 파일·기능, DB 최소 쿼리 결과를 확인합니다.
- 서비스 상태·디스크·로그 확인 결과를 기록합니다. 메모리 등 지표의 기본 제공 범위와 에이전트 필요 여부는 플랫폼별 확인합니다.
- AWS 실습 제출: 구성·웹 동작·저장소 접근·DB 연결·오류 해결·정리 결과.
- NHN 실습 제출: 동일 앱 결과, AWS 비교표, 운영 점검, 아키텍처 초안·선택 이유.
- 확인하지 못한 항목은 미확인으로 적습니다. 비밀정보 없는 증빙 주소와 설명을 LMS에 제출합니다.

## 6. 종료
다음 수업 재사용·공용 자원·개인 실습 삭제 대상을 먼저 구분합니다. 인스턴스 외 볼륨·DB·주소·스냅샷·백업도 확인합니다. 허용된 자원만 정리하고 남은 자원과 이유, 담당자를 기록합니다.
