# 승인된 LMS 학생을 기준으로 AWS 준비

## 운영 순서

1. LMS `/admin/lab-access`에서 과정을 고르고 관리자 LMS 비밀번호를 입력한 뒤 **승인 학생 명단 다운로드**를 실행합니다. 공개 과정의 승인된 STUDENT만 포함되며, 학생 ID·수강 ID·학번·이름·현재 이메일·기존 AWS 코드가 들어 있습니다. AWS 비밀번호와 운영자 키는 없습니다.
2. Ops → 교육 환경 일괄 준비 → AWS → 대상 환경의 **LMS 승인 학생 명단 가져오기 · 대조**에서 파일과 Cloud Ops 관리자 비밀번호를 입력합니다.
3. 대조 결과에서 포함할 학생과 코드를 확인하고 **대조 결과 확정 · 명단만 저장**합니다. 신규·알 수 없는 계정은 기본 선택하지 않으므로, 새로운 교육에서는 실제 참가 학생을 직접 선택하세요. 이름 일치는 제안일 뿐입니다. 본인·학번을 확인한 뒤 확정하세요. 과거 LMS 학생 ID 연결이 있으면 그 코드를 유지합니다.
4. 신규 생성·기존 자원 재사용·승인 명단에 없는 기존 자원 수를 확인합니다. 생성 기록이 없는 승인 학생만 선택할 수 있습니다. 기존 자원·비밀번호는 덮어쓰지 않습니다.
5. 한도 점검 후 필요한 학생만 생성합니다. 기존 환경이 이미 준비됐다면 생성 단계는 건너뜁니다.
6. **LMS 배정용 JSON 다운로드**는 확정한 승인 학생만 포함합니다. LMS 관리자 화면으로 가져오면 학생 ID와 수강 ID를 확인하여 배정합니다. 이메일이 바뀌면 최신 명단으로 다시 대조하세요.

## 현재 환경 전환

기존 명단에서 이메일이 변경된 경우 대조 화면에서 현재 가입 이메일을 확인합니다. 같은 이름만으로 확정하지 마세요. 미가입 학생은 승인 명단에 없어 신규 생성과 배정 JSON에서 제외됩니다. 해당 학생의 기존 자원은 남기며 자동 삭제·중지하지 않습니다. 자원 관리에서 승인 명단에 없는 기존 자원을 검토해 별도로 정리합니다. 나중에 가입·승인되면 새 명단을 다시 가져와 기존 코드에 연결합니다. 사용하던 코드를 다른 학생에게 재사용하지 않습니다.

## 명단의 유효 범위

명단은 관리자 화면에서 다운로드한 **시점의 승인 상태**입니다. LMS와 실시간 연동하지 않으며 파일 이후의 승인 취소를 자동 감지하지 않습니다. 생성 직전에 LMS 승인을 재확인하고 최신 파일로 대조하세요. 24시간이 지나거나 생성 대기 중 명단 버전이 바뀌면 생성·배정 내보내기를 차단합니다. 승인자가 0명이면 빈 명단도 확정할 수 있으며 생성 대상만 비활성화하고 기존 자원은 남깁니다. LMS에 배정할 때는 현재 승인 상태를 다시 검사합니다.

모든 명단 가져오기·확정은 관리자 권한·CSRF·비밀번호 재확인과 감사 기록을 거칩니다. 생성·삭제 진행 중에는 명단을 변경할 수 없습니다. 학생 ID와 코드 연결은 재배정할 수 없습니다. 과정을 변경하려면 별도 교육 환경을 만드세요. 파일은 개인정보이므로 운영자만 보관하세요.

## 배포

LMS의 승인 명단 다운로드와 Ops의 대조 기능을 모두 배포해야 합니다. Prisma/DB 스키마 변경은 없습니다. 기존 AWS/NHN 자원, 학생 IAM 비밀번호, 기존 ZIP, 학습 진도는 바꾸지 않습니다. Ops의 신규 AWS 생성은 명단 대조 전까지 차단되며 기존 학생 접속은 유지됩니다. NHN/NAVER 생성기는 이 AWS 흐름의 적용 대상이 아닙니다.
