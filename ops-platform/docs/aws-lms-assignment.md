# AWS 학생 환경을 LMS에 배정

먼저 [승인 명단 대조](lms-approved-roster.md)를 완료합니다. 신규 생성과 배정 내보내기는 최신 승인 명단에 확정된 학생만 허용합니다.

1. Ops → 교육 환경 일괄 준비 → AWS → 해당 환경 → **LMS 배정용 JSON 다운로드**.
2. 학생 코드·LMS 이메일을 확인합니다. LMS 승인 명단 대조 결과에서 가져오며 이메일 누락·중복·충돌이나 생성 미완료가 있으면 전체 다운로드를 차단합니다.
3. LMS 관리자 `/admin/lab-access`의 과정 ID를 입력합니다. 광주대 과정은 `gju-multicloud-2026`입니다. Ops 교육 ID나 과정 제목을 넣지 않습니다.
4. **Cloud Ops 관리자 비밀번호**를 입력하고 JSON을 받습니다.
5. LMS 관리자 `/admin/lab-access`에서 **관리자 LMS 비밀번호**를 입력한 뒤 **배정 JSON 파일 가져오기**로 파일을 선택합니다.
6. 연결 인원과 학생별 코드·열람 상태를 확인합니다. LMS에 가입하고 해당 과정 수강 승인을 받은 학생의 이메일과 정확히 일치해야 합니다. 오류가 나면 기존 배정과 이메일을 확인하고 AWS 자원을 다시 생성하지 않습니다.

JSON은 `version: 1`, `courseId`, `entries` 형식이며 실제 LMS 검증기로 호환성을 검사합니다. 학생용 ZIP의 `access.json`과 형식이 다릅니다. 다운로드만으로 LMS가 변경되지는 않습니다.

학생의 초기 IAM 비밀번호와 DB 비밀번호가 포함됩니다. 운영자 AWS Access Key·Secret Key·CloudFormation 입력은 포함하지 않습니다. 파일은 관리자만 보관하고 Slack 공개 채널·GitHub·학생에게 전체 전달하지 않습니다. 학생이 최초 비밀번호를 바꿨다면 그 변경된 비밀번호를 사용합니다. 이 기능은 AWS 비밀번호를 재설정하지 않습니다.

관리자 권한과 비밀번호 재확인, CSRF 검증, no-store 헤더와 감사 기록을 적용합니다. 실행 중인 생성·삭제 작업이 있으면 출력하지 않습니다. 기존 학생 ZIP·서버·DB·S3는 변경하지 않습니다.
