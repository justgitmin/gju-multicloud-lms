# NHN 기존 학생 프로젝트 일괄 준비

## 지원 범위

ADMIN 전용입니다. 프로젝트/서버를 새로 만드는 기능이 아니라, 기존 학생 프로젝트·서버를 검사하고 비공개 Standard 컨테이너와 선택한 학생별 사설 RDS를 준비합니다. 기존 IAM 역할, SSH 키, 웹 서버·VPC·서브넷·플로팅 IP는 변경하지 않습니다. 활성화/준비/정리는 명시적으로 실행합니다. 자동 재실행하지 않습니다.

각 학생이 이미 독립 프로젝트/VPC에 있으므로 이번 구현은 **프로젝트마다 RDS 1대**입니다. 공용 RDS와 프로젝트 간 라우팅을 묵시적으로 만들지 않습니다. 고가용성 없음, General SSD 20GB, 백업 보관 0일(훈련용), 사설 접속, 서버 사설 IP/32의 TCP 3306만 허용합니다. 학생별 RDS는 추가 과금됩니다. 정확한 금액을 예측하지 않습니다. 컨테이너만 먼저 준비할 수도 있습니다.

## 빠른 운영 순서

1. 기존 NHN 연결을 동기화하고, 해당 연결의 변경 허용을 켭니다. API 사용자/비밀번호는 운영자 계정이어야 합니다.
2. 교육을 등록합니다. NHN 일괄 준비 → 새 일괄 계획에서 기존 연결·교육을 선택합니다.
3. 조직 ID, 프로젝트 접두사 `TBIT_Edu01_Pro`, 서버 접두사 `gju-nhn-s`, 학생 시작/끝 번호를 입력합니다. 실제 서버 이름은 `gju-nhn-s01-web` 형식입니다. 이름이 다르면 계획이 차단됩니다.
4. 운영자 User Access Key / Secret을 **한 번** 입력합니다. 이전 역할 변경에 쓰던 키를 재사용할 수 있습니다. 키는 채팅이나 설정 파일에 붙이지 않습니다. 서버 DB에 AES-GCM으로 암호화 보관합니다. API 사용자/비밀번호는 기존 NHN 연결에서 가져옵니다.
5. DB 체크를 끄면 컨테이너만 준비합니다. 켜면 사양/버전 입력은 선택입니다. 비워두면 API 목록에서 최소 vCPU/메모리 사양과 MySQL 8.0 계열 최신 버전을 선택하여 계획에 표시합니다. 선택 알고리즘은 가격 비교가 아닙니다. 버전/사양이 없으면 차단하며 추측하지 않습니다.
6. 대상 조회·계획 만들기 → 작업 기록 종료 후 화면을 새로고침합니다. 프로젝트별 대상 서버·주소·컨테이너·DB 사양/버전과 차단 사유를 검토합니다. 이 단계에는 자원 생성 요청이 없습니다.
7. 서비스가 비활성 상태면 작업 이름·Cloud Ops 비밀번호를 확인하고 **Object Storage·선택 RDS 서비스 일괄 활성화** → **계획 다시 조회**를 실행합니다. 해당 프로젝트의 기존 서버·프로젝트는 만들지 않습니다. 서비스 활성화 API 권한이 없거나 리전별 설정이 추가로 필요하면 명확한 차단 상태로 남습니다.
8. 처음에는 번호 `1~1`로 파일럿을 실행합니다. 차단 항목이 없으면 작업 이름·Cloud Ops 관리자 비밀번호를 입력하고 일괄 생성을 실행합니다. 첫 생성 계획은 1시간 유효합니다. 이후 나머지 번호로 별도 계획을 만듭니다. 동일 이름/다른 소유 DB는 덮어쓰거나 비밀번호를 초기화하지 않습니다.
9. 준비 완료한 학생의 안내 JSON을 학생별로 내려받습니다. DB 비밀번호가 있으므로 해당 학생에게만 전달합니다. 운영자 키는 포함되지 않습니다. NHN IAM 로그인/PEM 키는 기존 개인 자료를 사용합니다. LMS 자동 배포는 구현 범위가 아닙니다.
10. 실제 학생 계정으로 비공개 컨테이너 업로드·다운로드, MobaXterm → `mysql -h 주소 -u labuser -p labdb` → `SELECT 1;`을 확인합니다. API 준비 완료와 학생 PC/서버의 실습 성공은 구분합니다.

## 상태·복구

- QUEUED/RUNNING은 작업 기록, PLANNED/BLOCKED/READY/FAILED 등은 학생별 상세 표입니다.
- 완료한 READY 학생은 재시도 시 건너뜁니다. 진행 도중 성공한 다른 학생의 자원은 롤백하지 않습니다.
- 모든 생성 요청 전에 암호화 저널/DB 암호를 저장합니다. 생성 요청 후 통신이 끊기면 이름·소유 표식으로 재조회합니다. 자원이 보이지 않고 이전 요청 결과가 불명확하면 중복 POST 대신 실패로 남깁니다. 운영자가 클라우드 작업 상태를 확인해야 합니다.
- 비동기 RDS jobId를 암호화 저널에 기록하고 성공 여부를 확인합니다. 요청 접수만으로 READY를 표시하지 않습니다. RDS 사용 가능 상태·스키마 생성·사설 접속 주소까지 검사합니다.
- 프로세스 재시작 시 기존 worker 정책대로 INTERRUPTED가 됩니다. 생성은 자동 재시도하지 않습니다. 상태 확인 후 실패 항목 재시도를 누릅니다.
- API 비밀번호/키를 바꿨다면 일괄 작업의 인증정보 갱신에서 현재 연결의 API 정보를 반영하고 UAK를 교체합니다. 생성 저널은 유지합니다. 실행 중에는 갱신을 막습니다.
- 생성 이력이 있는 계획은 다시 조회로 덮어쓰지 않습니다. 정리를 시작한 계획은 다시 생성하지 않습니다.
- 다른 교육에 배정된 서버는 자동 재배정하지 않습니다. 완료 시 조회 연결·서버를 교육에 등록하지만 새 연결은 조회 전용입니다.

## 정리

작업 이름·관리자 비밀번호를 확인하고 생성 자원 정리를 명시적으로 실행합니다. 기존 서버·네트워크·기존 비공개 컨테이너 재사용분은 보존합니다. 직접 생성한 RDS/보안 그룹/파라미터 그룹/컨테이너만 소유 표식과 ID를 확인합니다. RDS 데이터는 최종 백업 없이 삭제됩니다. 학생 파일이 남은 컨테이너는 보존하고 정리 확인 필요로 표시합니다. 파일을 백업·정리한 후 다시 요청합니다. 이 기능은 데이터 강제 비우기나 프로젝트/서비스 종료를 하지 않습니다.

## 필요한 권한과 인증

- 프레임워크: 조직 프로젝트 목록, 서비스 카탈로그, 프로젝트별 서비스 Appkey/외부 ID 조회, 선택 서비스 활성화 권한.
- 인프라: 서버 상세·네트워크 인터페이스 조회.
- Object Storage: 전용 Tenant ID/토큰, 컨테이너 조회·생성·삭제·메타데이터. 인프라 Tenant ID를 재사용하지 않습니다.
- RDS: Appkey + 운영자 UAK + Secret, RDS ADMIN에 준하는 생성/조회/정리 권한. 학생의 RDS VIEWER로는 운영자 생성 작업이 안 됩니다.
- 운영자 키를 학생에게 전달하지 않습니다. 원문 API 오류·키·생성 비밀번호는 대시보드/작업 기록에 표시하지 않습니다.

## 검증 범위

모의 API 응답을 사용해 계획/생성/소유권/재시도/정리/암호화/권한을 검증합니다. 실계정 생성은 운영자 키 입력·파일럿 실행 후 별도로 확인해야 합니다. 서비스 카탈로그/리전별 지원/쿼터/학생 계정 권한 등의 실제 조건에 따라 계획 또는 실행이 차단될 수 있습니다.

## 공식 API

- [Framework API](https://docs.nhncloud.com/ko/nhncloud/ko/public-api/framework-api/): 프로젝트 목록, 서비스 계층, 서비스 정보 externalId/Appkey, 서비스 활성화.
- [IaaS token](https://docs.nhncloud.com/ko/nhncloud/ko/public-api/iaas-token/): 인프라와 Object Storage의 프로젝트별 인증.
- [Instance API](https://docs.nhncloud.com/ko/Compute/Instance/ko/public-api/): 기존 서버/인터페이스 조회.
- [Object Storage API](https://docs.nhncloud.com/ko/Storage/Object%20Storage/ko/api-guide/): 컨테이너 HEAD/PUT/DELETE, Standard 클래스와 비공개 정책.
- [RDS for MySQL v3](https://docs.nhncloud.com/ko/Database/RDS%20for%20MySQL/ko/api-guide-v3.0/): 사양/버전/서브넷, PG/SG, 인스턴스/스키마 생성, 비동기 job, network-info, 정리.
