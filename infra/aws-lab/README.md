# AWS 온라인 영상 실습 — 공용 VPC / 학생별 자원 (v2)

현재 AWS 01–08 영상의 직접 미션에 맞춘 **제공 자원 사용형** 구성입니다. 운영자가 환경을 만들고 학생은 SSH·웹 배포·S3 파일·DB 연결을 실습합니다. 실제 AWS 배포 및 학생 간 접근 차단 시험은 아직 수행하지 않았습니다. 2명 파일럿 후 확대하세요.

## 구조

| 공용 네트워크 스택 `<lab_id>-shared` | 학생별 스택 `<lab_id>-s01`~`s15` |
|---|---|
| VPC 1개 / 인터넷 게이트웨이 / 라우팅 | IAM 사용자 / 개인 SSH 키 / Ubuntu 24.04 EC2 |
| 공용 웹 서브넷 1개 | 개인 웹 보안 그룹: SSH는 본인 집 공인 IP /32, HTTP 80은 공개 |
| 사설 DB 서브넷 2개 (서로 다른 AZ) | 선택: 개인 S3 버킷 / 개인 RDS MySQL / 개인 DB 보안 그룹 |

학생별 VPC를 만들지 않으므로 기본 VPC 한도 내에서도 **새 VPC 1개 여유**가 있으면 네트워크를 구성할 수 있습니다. 공용 VPC는 이 도구가 새로 만든 교육 전용 VPC이며 운영 중인 LMS VPC를 가져오지 않습니다.

- IAM은 본인 서버 시작·중지·재부팅, 본인 S3 `practice/` 파일 읽기·쓰기·삭제, 본인 비밀번호 변경만 허용합니다. 일부 EC2/네트워크 조회에는 다른 학생 목록도 보일 수 있습니다.
- 네트워크·보안 그룹·소유자 태그·IAM 정책 변경, 역할 전달, 신규 EC2/RDS 생성, 스냅샷/공유, 다른 서비스 생성은 허용하지 않습니다.
- 기본 보안 그룹은 학생 서버에 연결하지 않습니다. 각 DB는 대응하는 **본인 웹 보안 그룹**만 3306 접근을 허용합니다. 공용 VPC의 전체 CIDR을 DB 접근 출발지로 허용하지 않습니다.
- 웹 80은 실습 페이지 공개 확인용이므로 다른 학생도 접속할 수 있습니다. 모든 통신을 차단하는 완전 격리가 아니라 **관리 권한·SSH·DB 접근을 분리**하는 구성입니다.
- IAM 정책과 같은 permissions boundary를 설정합니다. 기존 계정의 리소스 정책/SCP까지 분석하지 않으므로 실제 계정에서 검증이 필요합니다. 추가 그룹/권한/직접 리소스 정책을 임의로 부여하지 마세요.
- EC2에는 AWS 자격 증명이나 IAM 인스턴스 역할을 연결하지 않습니다. 학생은 S3 콘솔 직접 링크를 사용합니다.

## 집에서 SSH 접속

`config.local.json`의 `ssh_cidrs`에 **학생별 집 공인 IPv4 /32**를 입력합니다. 학생 PC의 `192.168.x.x` 같은 내부 주소가 아닙니다. 학생은 집 인터넷에서 외부 IP 확인 서비스 등으로 공인 IPv4를 확인해 운영자에게 전달합니다. 예시 주소나 0.0.0.0/0은 실제 생성에 사용할 수 없습니다.

```json
"students": ["s01", "s02"],
"ssh_cidrs": {
  "s01": "학생01의실제공인IPv4/32",
  "s02": "학생02의실제공인IPv4/32"
}
```

학생별로 한 개의 공인 IPv4만 지원합니다. IP가 달라지거나 IPv6만 있는 망이라면 기존 IP 규칙으로 SSH가 안 됩니다. 공용 SSH 전체 개방으로 우회하지 말고 운영자에게 변경을 요청하세요.

**이번 버전은 운영자용 설정/갱신 도구입니다. 학생이 LMS에서 직접 IP를 등록하는 화면이나 AWS 관리자 키를 홈페이지에 연결하는 기능은 포함하지 않습니다.**

IP가 바뀌면 운영자가 아래 명령을 실행합니다. 해당 학생 스택 소유권과 SSH 규칙을 확인한 뒤 **본인 보안 그룹의 SSH 규칙 1개만 교체**하며 이전 IP는 제거됩니다. 학생에겐 보안 그룹 수정 권한을 주지 않습니다.

```bash
python3 infra/aws-lab/lab.py set-ssh --config infra/aws-lab/config.local.json --student s01 --ip 학생의새공인IPv4 --confirm-account 실제12자리계정ID
```

이 명령은 CloudFormation 스택 업데이트 없이 EC2 보안 그룹 규칙을 수정합니다. SSH CIDR의 스택 drift가 생기는 것은 의도된 동작입니다. 로컬 config의 `ssh_cidrs`도 같은 값으로 수정하세요. 스택 업데이트를 통한 재적용은 이 도구에서 지원하지 않습니다.

## 영상별 수행 범위

| 영상 | 학생 수행 | 사전 제공 |
|---|---|---|
| AWS 01 | 로그인·계정/서울 리전·범위 확인 | 개인 로그인 정보 |
| AWS 02 | VPC/서브넷/경로 조회·구조 그리기 | 공용 교육 네트워크 |
| AWS 03 | MobaXterm SSH 접속 | 본인 IP 허용·ubuntu 사용자·개인 키 |
| AWS 04 | Nginx 설치·예제 페이지 변경·내/외부 확인 | 빈 Ubuntu 서버, 저장소 `examples/demo-app` |
| AWS 05 | 본인 버킷 `practice/` 파일 업로드·확인·삭제 | 비공개 S3 및 직접 링크 |
| AWS 06 | 본인 웹 서버에서 DB 클라이언트 연결·최소 쿼리 | 본인 RDS 주소·labdb·labadmin·개별 비밀번호 |
| AWS 07 | 최소 권한 요청문 작성 | IAM 변경 권한 불필요 |
| AWS 08 | 증빙 제출·파일 삭제·서버 중지·정리 기록 | 최종 삭제는 운영자 수행 |

S3/RDS를 끄면 해당 업로드/DB 연결 미션은 수행할 수 없습니다. 전체 영상 실습은 둘 다 켭니다. Nginx는 자동 설치하지 않으므로 학생이 교안대로 설치합니다. 예제는 `index.html`만이 아니라 `examples/demo-app` 전체를 올립니다.

DB는 학생별 **별도 인스턴스**이며 `labadmin`은 본인 DB 관리자입니다. 공유 DB에 공용 관리자 비밀번호를 배포하지 않습니다. RDS 콘솔 권한은 주지 않으며 제공 주소로 연결합니다.

```bash
sudo apt-get update
sudo apt-get install -y mysql-client
mysql -h 제공된DB주소 -u labadmin -p labdb
```

프롬프트에 개별 DB 비밀번호를 입력한 뒤 `SELECT 1; SELECT DATABASE();`를 실행합니다. 비밀번호를 명령줄/제출물에 적지 마세요.

## 실행 준비

AWS 콘솔의 **CloudShell**에서 관리자 신원으로 실행하는 방식을 권장합니다. Python 3·AWS CLI v2·ssh-keygen 필요. LMS의 S3 읽기 전용 키를 관리자 키로 교체하지 마세요.

- 서울 VPC/인터넷 게이트웨이 각각 1개 여유가 필요합니다. 이미 이 도구의 공용 네트워크가 있으면 재사용합니다.
- 15명 기준 EC2 15대(선택 사양은 각각 2 vCPU), RDS 선택 시 15대, 공인 IPv4·EBS·S3 사용량을 준비합니다. EC2/RDS 한도와 비용은 별도로 확인해야 합니다.
- EC2·RDS·EBS·공인 IPv4·S3는 과금될 수 있습니다. 무료 사용을 보장하지 않습니다. NAT Gateway는 만들지 않습니다. 업로드/전송 비용까지 고정 상한을 보장하지 않습니다.
- 이전 학생별 VPC 도구로 만든 스택을 자동 변환하지 않습니다. 기존 환경이 있다면 정리 계획을 확인한 뒤 새 `lab_id`로 생성하세요.

## 1. 계획 확인 (AWS 변경 없음)

저장소 루트에서:

```bash
cp infra/aws-lab/config.example.json infra/aws-lab/config.local.json
nano infra/aws-lab/config.local.json
python3 infra/aws-lab/lab.py plan --config infra/aws-lab/config.local.json
```

설정:
- `lab_id`: 새 교육의 고유한 이름.
- `students`: 처음에는 s01/s02 두 명만, `ssh_cidrs`도 두 명과 정확히 일치해야 함.
- `ssh_cidrs`: 각 학생의 실제 집 공인 IPv4 /32.
- `instance_type`: t3.micro 또는 t3.small. `volume_gb`: 8–30.
- `s3`/`rds`: true 또는 false. `db_class`: db.t4g.micro 또는 db.t4g.small.

`plan`은 설정에 포함된 학생 자원과 공용 VPC 1개를 표시할 뿐 AWS 조회·생성·요금 추산·IAM 시뮬레이션을 하지 않습니다.

## 2. 생성

운영자가 설정/비용/한도를 확인한 뒤 실행:

```bash
aws sts get-caller-identity
python3 infra/aws-lab/lab.py apply --config infra/aws-lab/config.local.json --confirm-account 실제12자리계정ID
```

VPC/IGW 한도를 읽기 전용으로 점검 → 공용 네트워크 생성 또는 소유권 확인 후 재사용 → 학생 스택 순차 생성. RDS 생성에는 시간이 걸립니다. 실제 계정에서 CREATE_COMPLETE가 되어야 준비 완료입니다.

`.lab-state/<lab_id>-<student>/`에 콘솔 초기 비밀번호·DB 비밀번호(`credentials.json`), SSH 개인 키(`ssh-key`), 로그인/서버 IP/S3 링크/DB 주소(`outputs.json`)를 저장합니다. 폴더 0700, 비밀 파일 0600. **학생별 자료만 개별 전달하고 전체 자료를 단체방/Git에 올리지 마세요.** 첫 로그인 때 비밀번호를 변경합니다. 강제 MFA 정책이 있는 계정은 별도 MFA 등록 정책 설계가 필요합니다.

CloudShell 상태도 유실될 수 있으므로 생성 직후 운영자 전용 비공개 보관처로 옮기세요. 실패하면 중단하고 CloudFormation 이벤트와 생성 상태를 확인합니다. 기존 자격 증명 파일을 덮어쓰지 않습니다. `apply`는 스택 업데이트/자동 재시도를 지원하지 않습니다. 추가 학생 생성 시 기존 학생을 config에서 빼고 신규 학생만 넣으며 공용 네트워크는 재사용합니다. 전체 학생 목록은 삭제 시 쓸 수 있게 별도로 유지하세요.

## 3. 실제 2명 파일럿 검증

별도 브라우저 프로필에서 s01/s02 각각:
1. 첫 로그인/비밀번호 변경·본인 서버 SSH·웹 배포 확인.
2. 본인 S3 직접 링크의 `practice/` 파일 업로드/다운로드/삭제 성공. 전체 버킷 목록 조회는 허용하지 않으므로 직접 링크 사용.
3. 상대 S3 접근/객체 조작 실패, 상대 EC2 시작/중지/재부팅 실패 확인.
4. 신규 서버/서비스 생성·보안 그룹 변경·IAM 변경 실패 확인.
5. 본인 웹 서버→본인 DB 연결 성공, 본인 웹 서버→상대 DB 연결 실패 확인.
6. 집 IP 변경 명령 실행 후 새 IP 접속 성공·기존 IP 규칙 제거 확인.
7. 학생 하나만 삭제하면 상대 학생 서버/DB와 공용 VPC는 유지되는지 확인.
8. 마지막 학생 삭제 후 공용 네트워크까지 삭제되는지 확인.

실제 검증은 아직 미실행이며 계정의 정책과 최신 콘솔 동작에 따라 보완이 필요할 수 있습니다. 인스턴스 중지/시작 후 공인 IP가 바뀔 수 있습니다. outputs의 서버 IP는 생성 시점 값이므로 콘솔에서 현재 IP를 확인하세요.

## 4. 상태·삭제

```bash
python3 infra/aws-lab/lab.py status --config infra/aws-lab/config.local.json
python3 infra/aws-lab/lab.py destroy --config infra/aws-lab/config.local.json --confirm-account 실제12자리계정ID
```

**삭제는 해당 학생의 S3 파일과 DB를 최종 복구 스냅샷 없이 삭제합니다. 제출물은 먼저 보관하세요.**

삭제 대상 스택의 소유권 확인 → 해당 학생 권한 차단 → 전용 비버전 S3 비우기 → 학생 스택 삭제 대기. 마지막에 같은 LabId의 다른 학생 스택이 남아 있으면 **공용 네트워크 유지**, 남아 있지 않으면 공용 네트워크 삭제 대기. 기존 LMS 서버·영상 버킷·다른 LabId는 대상이 아닙니다.

삭제는 원자적이지 않습니다. 실패하면 남은 스택을 점검하세요. 이미 삭제된 학생은 config에서 제외하고 남은 학생만 재시도합니다. 버전 관리 버킷은 자동 비우지 않고 중단합니다. Object Lock·수동 추가 자원·외부 연결·보호 설정은 삭제를 막을 수 있습니다. 수동 스냅샷·백업·도구 외 생성 자원은 자동 정리 대상이 아닙니다. 로컬 자격 증명은 자동 폐기하지 않습니다. 최종 자원/과금 상태는 운영자가 확인하세요.
